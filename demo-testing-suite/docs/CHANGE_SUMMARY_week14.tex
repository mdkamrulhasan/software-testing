\section{Purpose of This Document}
% ============================================================
This document summarizes what was added for Week 14 and explains
\emph{why} each change exists --- which concept from the Week 14
reading, \textit{Advanced Testing, Emerging Techniques, and AI-Assisted
Testing}, it demonstrates. Read it alongside the reading
(\path{reading_materials/w14_advanced_ai_testing.pdf}) and
\path{demos/continuous_advanced_testing/README.md}.

\begin{keyidea}
Nothing from Weeks 1--13 was removed or changed in behavior. Week 14
adds to Week 13's folder: a consumer-driven contract between the shop
and PayFast, checked from both sides; two drift scenarios that every
other test misses; and two AI-generated test suites, kept exactly as
generated, with a script that measures what each one actually catches.
\end{keyidea}

\section{Contract Testing, Runnable}
% ============================================================
\begin{lstlisting}[style=shellstyle]
cd demos/continuous_advanced_testing
pytest tests/contract -v                                             # 7 passed
SHOP_PAYMENTS=no_idempotency pytest -q                               # 3 failed, 64 passed
PAYFAST=sandbox-next pytest tests/contract/test_payfast_provider.py  # 1 failed: id missing
\end{lstlisting}
In both drift scenarios, all of Week 11's tests pass: they talk to our
fake PayFast, which neither requires the header nor renamed the field.
Against the renamed field, the running shop charges the customer and
answers ``internal error'', leaving the order \texttt{pending}
(\texttt{python serve.py \dd payfast sandbox-next}).

\section{AI-Generated Tests, Measured}
% ============================================================
\begin{lstlisting}[style=shellstyle]

SHOP_COUPONS=per_unit pytest ai_generated/suite_from_code.py -q   # 41 passed
python ai_generated/evaluate.py ai_generated/suite_from_spec.py
\end{lstlisting}

The suite written from the code fails on the correct shop and passes on
the defective one: it encoded the code's misreading of the coupon
story. Neither AI suite can see the race or the missing header; the
specification-based one kills the three mutants the human suite misses.
Both suites are kept unedited; neither is collected by a plain
\texttt{pytest} (their names do not start with \texttt{test\_}).

% ============================================================
\section{How This Connects to the Reading}
% ============================================================
\begin{keyidea}
Every technique moves the oracle somewhere: a contract to an agreed
interface, mutation testing to the original program, AI generation to
whatever the model is shown. The shop's three known defects needed three
different kinds of test; no one technique, and no one suite, caught all
three alone.
\end{keyidea}
